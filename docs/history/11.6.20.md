# STEP11.6.20 — PogoDate CoreLibs object and scene classes

## Before

STEP11.6.19 removed Hillslide's `font.newFamily` failure and loaded its three
real PFT faces. Startup then stopped at `App.lua:88` with `attempt to call a
table value (local 'scene')`. The task retained 2,952 B of native stack, so
this was another Lua compatibility issue rather than stack exhaustion.

## Cause

PogoDate's original compact `class()` helper created callable classes but did
not reproduce the complete `CoreLibs/object.lua` instance layout. On Playdate,
each instance stores its concrete callable class in `instance.super`. PogoDate
instead exposed the parent table through lookup. A scene manager which saved
that value and later executed `scene()` therefore attempted to call an ordinary
table.

## Changes

The object layer now follows the official SDK 3.0.5 behavior for:

- concrete `instance.super` class links and callable scene reconstruction;
- `class`, `className`, `baseObject`, `init` and `isa` relationships;
- class property tables and optional namespace registration;
- inherited Lua metamethods used for operators and object presentation;
- subclass allocation through the parent's `baseObject()`;
- the SDK's nil return from `class(...).extends(...)`;
- `Object:tableDump()` and `printTable()` debugging helpers.

Sprite subclasses expose the same class metadata and allocation hook without
changing PogoDate's existing sprite storage. The font-family constants are now
the SDK's numeric normal/bold/italic variants, while string-keyed families
remain accepted. `graphics.getTextSizeForMaxWidth()` also uses the documented
argument order: text, maximum width, leading adjustment, then font.

## Result

A dedicated regression recreates Hillslide's failing scene pattern: construct
a namespaced scene instance, save its `instance.super` table, then call that
table to construct the next scene. It also covers property-backed classes,
custom `baseObject`, inheritance, `isa`, copied metamethods and sprite
subclasses.

The rebuilt suite additionally passes the real three-PFT family probe,
Godspeed through game over, Frogger startup, Celeste 300 logical frames, Maze
900 frames, Duel Of Shadows 1,800 frames, input responders, crank, synth and
deep-SFX probes. WOOD's eight progression captures are byte-identical to
STEP11.6.19.

The user's Hillslide PDX remains the final hardware proof. STEP11.6.20 should
pass `App.lua:88`; the next complete Lua error, if any, identifies the next
package-independent API gap.
