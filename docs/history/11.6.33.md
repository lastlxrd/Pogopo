# STEP11.6.33

This step restores the normal visual-effects path used by XTRIS and other
Playdate packages, corrects short ADPCM sample decoding, and raises the SDMMC
bus speed with a safe fallback.

## Graphics and accessibility

- playdate.getReduceFlashing() now defaults to false. PogoPo does not yet
  expose a system accessibility toggle, so returning true forced every game
  into reduced-effects mode without the user's request.
- Image-less sprite draw() callbacks now render against the framebuffer with
  a sprite-local origin. Screen clips, stencils and drawing outside the nominal
  sprite bounds therefore retain Playdate semantics.
- XTRIS consequently uses its large dithered score images, baked goal
  particles, animated fire and ordinary movement effects.

## Audio

- IMA ADPCM nibble decoding now uses the standard separately-rounded step
  fractions. The previous algebraic approximation accumulated predictor error,
  which was most noticeable on short UI clicks.

## Storage

- Four-bit SDMMC now requests the supported 40 MHz high-speed mode instead of
  the 20 MHz default.
- A failed high-speed mount is retried at 20 MHz so marginal cards or wiring do
  not prevent boot.
- The mount log reports the negotiated clock.

## Regression coverage

- XTRIS: 3,000 frames through the timed game-over transition, zero Lua errors.
- XTRIS effects: dither score, goal particles and fire verified from captured
  framebuffer images; sound assets use PCM with no Error fallback.
- Binairo Continue: 360 frames, zero Lua errors.
- Maze: 900 frames, zero Lua errors.
