# STEP11.6.19 — PogoDate font-family compatibility

## Before

STEP11.6.18 removed Hillslide's native task-stack overflow. The game then
loaded all 35 Lua modules and reached `App.lua`, where startup stopped at line
23 because `playdate.graphics.font.newFamily` was missing. The reported
`pogopo_os` minimum of 2,872 B confirms this is a normal compatibility gap,
not a recurrence of the stack failure.

## Changes

`graphics.font.newFamily()` now builds SDK-style families keyed by
`normal`, `bold` and `italic`, loading each package PFT through the existing
compiled-font decoder. `graphics.setFontFamily()` and `getTextSize()` accept
the resulting family directly.

The neighboring text surface was completed at the same time: font-object
tracking and leading, global font tracking, font-object text drawing and
alignment, glyph image extraction, `getTextSizeForMaxWidth()`, wrap and
alignment constants, and the documented width/height/truncation results from
`drawTextInRect()`. PFT tracking is applied exactly once; global tracking is
then added independently.

## Result

A host probe starts the real 53-module Maze PDX, creates a three-face family
from three real PFT resources, switches it into the graphics context, measures
and draws text, changes tracking and leading, extracts a glyph image and tests
bounded text sizing. It passes with no Lua errors.

The rebuilt regressions also pass input responders, crank and synth probes,
the seven-level stack-safe SFX package, Maze for 900 frames, Duel Of Shadows
for 1,800 frames and the STEP11.6.17 graphics/sprite/pathfinder suite. WOOD's
eight progression captures are byte-identical to STEP11.6.18.

Hillslide itself remains an on-device test because its package is not included
in this source archive. Its next run should pass `App.lua:23`; any later full
Lua error is the next package-independent API target.
