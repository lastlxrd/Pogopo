# STEP11.6.17 — Playdate game compatibility

## Before

STEP11.6.16 filled the general geometry, JSON and graphics gaps, but many small
2D games could still stop on common sprite queries, tilemap mutation, generated
image helpers or the SDK pathfinder. Those calls sit below bundled CoreLibs and
game frameworks, so one missing leaf could prevent an otherwise compatible Lua
`main.pdz` from reaching its first frame.

## Changes

PogoDate now implements point/line sprite queries with ordered hit metadata,
sprite bounds/copy/stencil/state helpers, mutable tilemaps and merged collision
rects, anchored/cropped/rotated/masked/affine-transformed images, text images,
additional geometry and graphics operations, and an inspectable A* pathfinder
with graphs, nodes, weighted connections and 2D-grid construction. Wall sprites
now use the tilemap's real tile dimensions. The step adds or expands 92 named
Lua methods without package-name or asset-specific workarounds.

## Result

The dedicated game-compatibility regression passes alongside input, crank,
synth, Maze, Duel and WOOD tests. Maze completes 900 logical frames and Duel
1,800 with zero Lua errors. WOOD keeps its authored 20 FPS rate and all eight
captured progression frames remain byte-identical to STEP11.6.16.

This is a much broader base for testing other free Lua/PDZ games, but it is not
full Playdate OS: native `pdex.bin`, networking, microphone, video, extensions
and the complete sound instrument/sequence/modulation stack remain outside this
step. Final LCD, SD, BMI270 and speaker behaviour still requires Pogopo hardware.
