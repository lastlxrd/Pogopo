# STEP11.6.25 — native polygon terrain rasterizer

## Before

STEP11.6.24 cached expanded PDT streams and removed explicit full Lua
collection. A new Pogopo hardware trace disproved PDT inflation as the main
remaining Hillslide bottleneck: each PDT decoded in only 6–67 ms, LCD blitting
stayed near 5–7 ms, but creation of each new hill segment still blocked Lua
logic for 1.18–1.32 seconds. During that pause the previous terrain sprites
continued leaving the viewport, producing the visible half-map and then
full-map disappearance, five-second movement gaps and interrupted audio.

## Cause

`graphics.fillPolygon()` was a Lua fallback. For every scanline it allocated a
new intersections table, traversed every polygon edge, sorted the table and
called the native line primitive again for each filled span. Hillslide creates
each hill render target from a solid polygon plus six patterned polygon passes,
so one segment performed hundreds of Lua table allocations and thousands of
Lua-to-C++ transitions. This cost was recorded as game `logic`, not `blit`.

Pattern spans then used the generic per-pixel compositor. The compositor
rechecked clipping, stencil state and image content bounds for every pixel even
when a scanline had already been clipped and the active draw mode was a simple
pattern Copy into an image target.

## Changes

- added native numeric and `playdate.geometry.polygon` argument decoding;
- added native `drawPolygon`, `fillPolygon`, `drawTriangle` and `fillTriangle`;
- kept open-polygon draw behavior and closed-polygon validation for fills;
- scan-convert only rows intersecting the active clip and render target;
- fill complete horizontal spans in C++ instead of calling back through Lua;
- added a direct patterned Copy-mode span writer for image and screen targets;
- retain image patterns, byte patterns, transparent patterns, offsets,
  inversion, stencil fallback and existing content-bound tracking;
- keep the Lua implementations as fallbacks for runtimes without the native
  entry points rather than overwriting the accelerated functions.

## Result

A focused host benchmark drawing 100 large patterned polygons falls from about
16.9 ms on STEP11.6.24 to 1.25 ms on STEP11.6.25, roughly 13.5 times faster.
The full Hillslide suite opens all nine scenes and completes 500 Training plus
1,000 gameplay frames with zero Lua errors. Captures at gameplay frames 10, 30
and 90 are pixel-identical to the previous renderer; later scene state remains
structurally correct.

The benchmark ratio is not an ESP32-S3 FPS promise, but it removes the exact
Lua allocation/sort/call pattern measured in the device's 1.2-second logic
stalls. API coverage remains roughly 226–236 of 262 useful non-crank Lua calls;
this step improves the performance and fidelity of four existing graphics APIs
rather than inflating the count with new stubs.
