# STEP11.6.24 — Hillslide runtime performance and API coverage

## Before

STEP11.6.23 corrected Hillslide's timer arguments and cut the live Lua heap
from about 4.85 MiB to 0.91–0.95 MiB. Hardware still rendered only 1–21 FPS.
Ordinary logic frames took 39–81 ms and a recurring logic update took
1.29–1.37 seconds. LCD transfer remained only 5–7 ms, proving that neither the
Sharp panel nor SPI was the main bottleneck.

## Cause

A compiled PDT is one zlib stream containing its complete offset table and all
frames. STEP11.6.23 kept this stream packed to save memory, but inflated the
entire table every time a requested frame was absent from the 48-frame Lua
cache. Hillslide changes both animation frame and snowboarder angle, so cache
misses repeatedly expanded tables as large as 471,244 bytes.

The generic compact-image renderer also called `imagePixel()` for every source
pixel. That reparsed the same 16-byte image header, recomputed plane sizes and
revalidated mask bounds thousands of times per draw.

Finally, when all six reusable large-image planes were owned by persistent
terrain targets, allocating a temporary target forced `LUA_GCCOLLECT`. On the
ESP32-S3 this stop-the-world fallback matched the remaining long periodic
pauses visible in the hardware log.

## Changes

- added a 1.4 MiB expanded-PDT PSRAM LRU shared by live image tables;
- inflate an active PDT once and copy requested native 1-bit frame payloads
  from it without another zlib pass;
- evict only the least-recent expanded stream; images already returned to Lua
  remain valid because each owns its compact frame data;
- added PDT cache logs with path, bytes, decode time and current budget use;
- added a direct compiled 1-bit compositor that parses metadata once per draw,
  clips to stored content and supports masks, all flips, inversion and the
  common draw modes;
- removed the full-GC large-image fallback; overflow render targets now own an
  external PSRAM plane reclaimed by normal incremental Lua collection;
- added `display.setMosaic/getMosaic`, hardware X/Y `display.setFlipped()` and
  `display.loadImage()` compatibility;
- added keyboard show/hide/text/lifecycle/capitalization compatibility;
- added neutral mic/headset and output-selection APIs so games can accurately
  feature-detect hardware which Pogopo does not contain.

## Result

The complete Hillslide host suite opens every one of its nine scenes, runs 500
Training frames and 1,000 gameplay frames with zero Lua errors. Four captured
gameplay checkpoints retain the expected terrain, HUD and animation layout
without a structural rendering regression. Desktop timing is not used as the
performance verdict because host zlib, malloc and Lua GC costs differ sharply
from ESP32-S3 PSRAM. Repeated full PDT inflation and explicit full Lua
collection have both been removed from the hardware path; final FPS must be
measured on Pogopo.

The API probe also validates keyboard lifecycle, missing-mic/headset results,
display mosaic state and display flip calls. Estimated usable Lua SDK coverage
is now roughly 226–236 of 262 non-crank callable entries, leaving about 26–36
(10–14%), mostly network, real keyboard/mic/video UI, simulator/debug services
and the advanced sound graph.
