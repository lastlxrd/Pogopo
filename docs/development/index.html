Development

A concise view of what works today, what remains experimental, what is planned, and how the current firmware is built.

Working

  • WorkingESP32-S3 board bring-up and diagnostics for the TCA9555, BMI270, BQ24295, Sharp display, SDMMC, I²S audio, and memory state.
  • WorkingPogopoOS launcher, app manager, 1-bit graphics, settings, quick menu, startup/outro animation, and controlled shutdown.
  • WorkingControls, motion, haptics, audio, storage, battery status, persistent preferences, and on-device test apps.
  • WorkingClassic Game Boy runtime with fixed-rate audio, SD-card ROM browser, ordered dithering, save handling, and the documented 59.7 Hz / ~29.9 Hz performance split.

Experimental

  • ExperimentalThe right-side mechanical/electrical module interface and its future PogopoOS discovery model.
  • ExperimentalPlaydate-style and other runtime research. A launcher entry or library placeholder does not mean general compatibility.
  • ExperimentalNative package format, public game template, and a larger Pogopo software library.
  • ExperimentalFormal long-duration reliability, power, thermal, storage, and task-latency characterization.

Planned

  • PlannedFreeze and publish the verified module connector, limits, protocol, and mechanical envelope.
  • PlannedAdd hardware block diagrams, software/task diagrams, PCB details, enclosure specifications, and measured power data.
  • PlannedAdd final console, PCB, close-up, and on-device gameplay media to the Gallery.
  • PlannedPublish a project license and clarify the public release scope for hardware and firmware sources.

Build and flash

The current documented environment is ESP-IDF 6.0.2 targeting esp32s3. Run the commands from the repository root and replace COM7 with the console’s serial port.

ESP-IDF terminal
idf.py set-target esp32s3
idf.py build
idf.py -p COM7 flash monitor

SD card layout

The card is mounted as a FAT filesystem over four-bit SDMMC. Game Boy ROMs use the .gb extension under /gameboy.

Current content layout
/gameboy/
  Tetris.gb
  Kirby's Dream Land.gb
/pogopo/
/playdate/

/pogopo and /playdate are library locations/placeholders; no stable public package format is claimed yet.

Application workflow

New native screens implement the shared application interface, are registered with the app manager, and use existing services for drawing, input, audio, haptics, storage, motion, power, and settings. Hardware testing must cover entry/exit, quick-menu suspend/resume, return navigation, and real Sharp LCD timing.

Project layout

The repository is a normal ESP-IDF project. Reusable system services live under components/; board pins, app registration, startup, and built-in apps are connected from main/. Generated 1-bit assets are committed with the firmware code that consumes them.

Development history

The repository README records the sequence of launcher, power, quick-menu, Game Boy, display, audio, and memory changes. It remains a useful implementation history, but the pages in this site describe the current architecture and verified baseline.
