System

Modularity

The right side of pogopo is intended as a mechanical and electrical expansion area for interchangeable hardware.

Core conceptWork in progress

The idea

pogopo is meant to remain useful beyond a fixed set of games. A module can extend the base handheld for a specific task, then be removed when it is no longer needed. The console keeps the display, controls, battery, storage, and PogopoOS runtime; the module adds task-specific hardware.

Possible categories include extra controls, sensors, wireless functions, storage, or experimental electronics. These are examples of the intended design space, not a list of completed products.

Mechanical expansion

The attachment area must locate a module consistently, resist normal handheld loads, and allow removal without damaging the console. It also has to fit the enclosure geometry and keep the device comfortable to hold.

Work in progress: final retention method, envelope, insertion cycle target, and module enclosure rules are not yet documented.

Electrical expansion

The electrical side needs a defined connector, power budget, voltage levels, signaling, and protection behavior. PogopoOS will also need a predictable way to detect a module and expose it to applications.

Not frozen yet

No connector pinout, bus allocation, current limit, hot-plug behavior, or module protocol is claimed here. Those details stay WIP until they are verified on hardware.

Software model

The intended software boundary is a device service that recognizes the attached hardware and presents a stable API to applications. Apps should not need to reproduce low-level bus handling for every module.

Design constraints

Base device first
The console should remain fully usable with no module attached.
Clear ownership
PogopoOS should own detection and drivers; applications should consume higher-level services.
Electrical safety
Power and signals need defined limits before modules can be considered compatible.
Honest compatibility
A module is supported only after both mechanical fit and electrical/software behavior are tested.

Current status

ExperimentalThe modular expansion area is a central product direction, but the public interface specification and verified module list are not complete.
