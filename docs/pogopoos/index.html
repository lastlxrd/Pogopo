System

pogopoOS

PogopoOS is the embedded C++ firmware that turns the custom board into a handheld platform. It owns hardware services, the 1-bit interface, applications, power behavior, and emulator integration.

ESP-IDF

The current firmware targets ESP-IDF 6.0.2. It uses ESP-IDF drivers for SPI, I²C, I²S, SDMMC, ADC, timers, heap capabilities, non-volatile settings, and FreeRTOS task scheduling.

Application and launcher architecture

A shared AppManager coordinates applications and provides access to graphics, input, haptics, audio, storage, motion, power, and settings services. The launcher selects Pogopo, Game Boy, Playdate, or settings libraries and opens the matching app.

The launcher, settings screens, diagnostics, file browser, and Game Boy wrapper use the same application boundary. This keeps device ownership centralized instead of letting each screen initialize hardware independently.

Graphics

The graphics component provides a canvas, bitmap and sprite drawing, text rendering, clipping, widgets, and a single Sharp LCD presentation path. The 1-bit design is intentional: system screens and game output share the same monochrome visual constraints.

Display

The Sharp LS027B7DH01 driver keeps a 12 KB 1-bit framebuffer in internal RAM when possible. It supports dirty-row updates and a 14 MHz full-screen fast path, uses DMA staging memory, and maintains the panel’s VCOM requirement in a dedicated task.

Input

The input service polls the TCA9555 for the eight front controls and reports pressed, held, and released state to applications. I²C failures use a released-sample fail-safe. The dedicated Power button is handled separately so a short press opens the quick menu while a hold starts shutdown.

Audio

The audio service owns the MAX98357A I²S output, system tones, WAV playback, and the emulator’s real-time stream. The Game Boy path remains fixed at 32,768 Hz; buffer underruns are surfaced in diagnostics instead of changing playback speed and pitch.

Storage

microSD is mounted as a FAT filesystem over four-bit SDMMC. The storage component lists files, loads WAV data, and provides the file paths used by the Game Boy browser and other content-driven apps.

Motion

The BMI270 service reads accelerometer and gyroscope data over I²C. Current firmware includes a motion/IMU diagnostic app; wider gameplay use remains application work.

Haptics

The haptics component drives the board’s vibration output and gives system screens and applications a shared way to request tactile feedback.

Settings

Persistent preferences include volume and UI feedback behavior. The settings area also exposes controls, audio, haptics, motion, system status, and About screens for on-device validation.

Power management

The power service reads charger state and battery voltage, distinguishes short and held Power presses, and prevents the boot-time button release from becoming a false quick-menu event. Shutdown saves state, blocks ship mode while USB is present, clears the physical LCD, and then requests BQ24295 ship mode.

The 25-frame shutdown overlay begins after a short hold delay. Releasing Power before completion reverses the animation and restores the suspended application.

Games and applications

The current tree includes the launcher, libraries, settings, hardware diagnostics, graphics/input/audio/haptics/motion tests, a WAV player, and the Game Boy browser/application. Pogopo and Playdate library screens are present as places for future content; their presence does not imply general Playdate compatibility.

Emulators

WorkingThe Game Boy runtime integrates Peanut-GB for CPU/PPU emulation and MiniGB APU for audio. ROMs are read from /gameboy/*.gb. The current performance path targets every 59.7 Hz emulated frame while presenting approximately every second LCD frame.

ExperimentalOther runtimes have been explored separately, but they are not listed as production capabilities until their performance and compatibility are verified.
