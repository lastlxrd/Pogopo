Engineering

Measured notes from the work behind Pogopo: display timing, emulation, memory placement, audio, task scheduling, and board reliability.

Display performance

The first ESP-IDF display path drove the Sharp panel at 2 MHz. Sending a complete 400 × 240 frame took about 49 ms on the wire, so a 30 FPS presentation target was impossible before any application work was counted.

Comparison with the stable Arduino firmware exposed the clock regression. The bus now runs at 14 MHz, unchanged rows are skipped, DMA staging stays in internal memory, and full-screen output uses a direct path. A worst-case transfer is roughly 7 ms, and the established Game Boy baseline presents about 29.9 visible frames per second.

Game Boy emulator optimization

Large ROMs stored in PSRAM originally slowed both emulation and presentation. The performance log was split into emulated frames, LCD frames, ROM-cache activity, audio state, heap state, and I²C errors; that made it clear that CPU progress and display rate were separate limits.

The emulator now advances CPU, timers, interrupts, input, and APU state for every 59.7 Hz Game Boy frame while drawing alternate frames to the LCD. ROMs that do not fit in internal memory stay in PSRAM behind an adaptive 16 KiB-page cache with bank 0 pinned and LRU replacement. The resulting baseline is full-rate emulation with roughly 29.9 Hz presentation.

Memory, PSRAM, and internal RAM

PSRAM holds large assets well, but the display framebuffer, DMA buffers, task stacks, and hot cache pages need internal RAM. Heap diagnostics therefore track both total free memory and the largest contiguous block instead of reporting one reassuring number.

Game Boy shades are packed at two bits per pixel, reducing three 160 × 144 buffers from 69,120 to 17,280 bytes. The current startup policy reserves an aligned internal arena while preserving headroom for the OS; Game Boy uses it for ROM data or bank-cache pages, and PogoDate can borrow the idle arena for its 96 KB screen buffer. That arrangement keeps latency-sensitive rendering away from PSRAM without permanently dedicating the memory to one runtime.

Audio buffering

Generating audio inside each video frame made slow rendering audible. Increasing or decreasing the playback rate could hide a draining buffer, but it also changed pitch, so it was not a valid fix.

MiniGB APU and the MAX98357A now remain locked to 32,768 Hz. A Core 0 producer feeds an internal ring buffer and the higher-priority I²S task consumes it at the hardware clock. Video timing can fluctuate without retuning the game, while underruns are counted and softened with a short fade.

FreeRTOS task and core organization

Emulation, I²S output, display work, controls, motion, and power services do not have the same latency requirements. Core 1 runs the emulator and its input path. Core 0 owns fixed-rate I²S, APU generation, the BMI270, power and VCOM services, and the lower-priority PogopoOS presentation loop.

The priorities are explicit, and long-running runtime work yields to the scheduler instead of relying on incidental delays. Serial timing and watchdog reports remain part of the acceptance check because a higher average frame rate is not useful if an idle task can still be starved.

Hardware debugging

Board bring-up has to separate a wiring fault from a bus fault and both from bad software state. Startup probes the TCA9555 at 0x20, BMI270 at 0x68, and BQ24295 at 0x6B, then records identity, configuration, charger status, and fault registers.

The system-status screen and dedicated test applications expose controls, audio, haptics, motion, power, display behavior, internal RAM, and PSRAM. A failed feature can therefore be traced back to a named peripheral and its current register state.

Storage and peripheral reliability

Removable storage and shared I²C devices can fail at inconvenient moments, so the firmware treats those failures as normal states. SD mounting never formats a card on failure, paths are bounds-checked, and file loaders validate type and allocation limits before accepting content.

TCA9555 reads use a 10 ms timeout and fall back to a released button state. Game Boy saves are deferred outside the emulator’s critical path and flushed when the app exits or the device shuts down. These choices prevent a transient bus error from becoming a held direction and keep an interrupted save from being mixed into frame timing.
